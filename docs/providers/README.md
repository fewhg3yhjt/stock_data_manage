# 源头采集接口

[源头采集接口说明](源头采集接口说明.xlsx) 记录当前源头采集输入的调用参数、字段映射、采集限制和验证范围。配套的 [生成数据与来源索引](源头采集接口说明.json) 保存各项配置、执行报告、派生输出及证据清单的哈希关联。

## 说明范围

- “接口总览”列出当前64项已实现的验证输入，分别记录数据周期、刷新频率、请求间隔、调度启用状态和生产路由状态。
- “调用参数”记录请求、配置、元数据和依赖参数来源，采用已核对执行报告中的实测参数作为示例。无参数接口明确说明来源快照或目录范围。
- “采集字段与映射”读取当前数据集字段模板和对应输入的唯一归一化规则；未独立核准的单位、未提供的字段和标准输出置空处理明确列出。
- “暂不纳入及历史”保留未完成接入、语义或覆盖受限的能力，以及别名和已拆分复合记录；不重复计入已实现输入。

64项执行报告均为已归档原响应的离线回放结果；报告的返回行数和覆盖分母只描述其实际样本。它们不能替代当前在线可用性、全市场完整性或持续采集容量验证。历史报告绑定当时的代码版本，本表中的配置和字段映射则读取生成时的当前版本。

同花顺年度每股收益预测与主营业务暂不纳入本轮采集：复用2026-10-04原请求120秒未返回及归档检索证据，缺可回放成功HTML；尚不能认定来源永久不可用。本次没有重复发起网络请求，也没有修改来源配置、调度或生产路由资格。

来源接口实际数据范围与调度覆盖配置分列。例如，公告及公司动态按明确日期查询全市场，ST名称名单仅沪深，腾讯快照默认配置为全股票盘后每日一次，但当前批量完整性验证与自动调度尚未启用。

## 配置依据与证据

| 依据 | 内容 |
|---|---|
| [providers.yaml](../../config/providers.yaml) | 输入能力、调用参数来源、请求形态和请求间隔 |
| [collection.yaml](../../config/collection.yaml) | 刷新频率、执行日历和调度覆盖配置 |
| `config/datasets/` | 标准字段、类型、单位和主键 |
| `config/normalization/` | 每项输入的来源字段映射与转换规则 |
| [现有输入工厂](../../src/routing/factory.py) | 已实现输入与调用方法的绑定 |
| [Provider 验证目录](../../provider_validation/README.md) | 原始响应、执行报告与原实现对照记录 |

Excel 是派生说明，修改它不会修改采集配置。表内证据、代码和YAML路径以仓库根目录为基准，保存为可检索的文本路径；本文提供主要文件的可点击入口。后续来源选择、回退、质量规则、数据构建、发布和业务查询文档分别归入对应模块目录，本文只记录采集输入及其当前字段映射。

正式源码现已直接位于 `src/`；当前代码入口使用新路径，已归档报告中的 `historical_code_files` 保留报告生成时的路径及哈希。目录迁移不改变原验证范围，也不重新授予生产路由资格。

## 刷新方法

在仓库根目录使用项目Python环境执行现有报告生成器的正式说明模式：

```powershell
python -m pip install -e .
python provider_validation/tests/build_interface_coverage.py --formal-spec
```

再用配置好 `@oai/artifact-tool` 的工作区Node环境导出阅读版；`CODEX_VISUALIZATION_DIR` 指向有依赖连接的当前工作区目录，预览和表格检查结果保存在该目录：

```powershell
node provider_validation/tests/build_interface_coverage_workbook.mjs --formal-spec
```

两步分别刷新配套JSON和XLSX。它们仅复用已提交审计索引中有哈希关联的成功执行报告，不采集新数据。原测试覆盖报告的默认导出模式及存放位置保持不变；旧证据哈希不匹配时不授予新的验证结论。

本次目录迁移后的导出核对记录见 [正式接口说明核对结果](../../provider_validation/results/source-layout-20261005/formal/verification.json)，迁移与安装验证见 [目录整理核对结果](../../provider_validation/results/source-layout-20261005/verification.json)。2026-10-04 的原导出核对记录保留原样。
