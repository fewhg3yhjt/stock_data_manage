# 只读运行台容器部署

## 部署对象与边界

本方案只容器化现有只读运行台，不把采集任务、后台调度或新的数据服务加入容器。Compose 从项目根目录启动 `stock-data-web`，读取现有配置和 `data/` 产物；页面本身不修改任务、原始响应或发布数据。

由 `Dockerfile` 提供 Python 3.12 和项目 `.[web]` 依赖。Compose 将宿主机项目目录以只读方式挂载到容器内相同绝对路径，并将 `data/` 以只读方式挂载到其原路径。因此更新 Python 源码或 YAML 后，重启容器即可加载，不需要重新构建镜像。依赖、Python 版本或系统运行环境变化时才需要重新构建镜像。

宿主机项目根目前预期为 `/opt/stock_data_manage`。容器内保持相同路径，避免历史报告中保存的宿主机绝对路径失效。若部署到其他位置，须先检查报告和证据引用中的绝对路径；运行台不会替换或迁移这些引用。Compose 要求宿主机项目根和 `data/` 都已存在，缺少时会启动失败而不会自动创建空目录；上线前应先确认数据目录权限及内容。

## 启动与更新

在项目根目录执行 `docker compose up -d --build` 首次构建并启动。默认只将宿主机 `127.0.0.1:8765` 发布到容器服务，便于由宿主机现有反向代理转发；不应直接把该端口暴露到公网。

代码或配置更新后执行 `docker compose restart stock-data-web`。容器使用源码挂载，所以不需要构建或拉取新镜像。修改 `pyproject.toml` 依赖、基础 Python 版本或镜像运行环境时，执行 `docker compose up -d --build` 更新运行环境。

停止服务使用 `docker compose stop`；移除容器使用 `docker compose down`。数据来自宿主机 `data/`，不属于容器可写层或 Compose 命名卷；不要为本服务配置数据卷清除操作。

可通过 `STOCK_DATA_WEB_PORT` 更改宿主机端口。仅当反向代理确实运行在其他主机/容器且有明确网络边界时，才调整 `STOCK_DATA_WEB_BIND`。端口映射范围以宿主机防火墙及代理配置为准。

## 文件与运行安全

- 项目代码、配置和数据挂载均为只读；页面下载响应只向客户端返回字节，不会在运行目录写文件。
- 容器默认使用 UID/GID 1000；可通过 `STOCK_DATA_WEB_UID` 与 `STOCK_DATA_WEB_GID` 调整为宿主机普通用户身份，保证只读访问权限匹配。
- Docker build context 排除 `data/`、验证证据、临时目录、测试、Git 元数据和本地环境文件；敏感配置及生产数据不会复制进镜像。
- 容器内服务监听 `0.0.0.0` 以接受 Docker 转发；宿主机端口默认仅绑定 `127.0.0.1`。应用的 `--allow-network` 不提供认证或访问控制。
- 页面能查看并下载原始响应。远程访问前，须由受控反向代理提供 HTTPS 和认证，并限制允许访问的用户；本 Compose 不实现登录或多用户权限。
- 容器有 HTTP 健康检查、自动重启和有限大小的 Docker JSON 日志；健康状态只表示 Web 首页可访问，不代表数据完整或采集任务成功。

## 验收

部署验收应确认 Compose 配置可解析，容器健康，首页可访问，非本机网络不能绕过反向代理直接访问；分别修改源码和 YAML 后重启并确认服务加载新版本；确认容器无法写入代码、配置和 `data/`，并能按历史绝对路径读取被引用的来源报告与原始响应。容器健康检查不能替代业务数据或来源资格验收。
