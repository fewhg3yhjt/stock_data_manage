# 输入能力框架第一阶段

本阶段将已验证返回整理为输入能力契约（Input Capability Contract），并在现有配置、适配器、路由、元数据和传输模块内补齐参数绑定、请求节奏与证据边界。覆盖范围和调度执行留待下一阶段确定。没有新增能力管理服务、数据库或生产任务。

## 数据依据与可复查清单

来源为 `coverage/interface-coverage.xlsx`、对应 CSV 和 `results/interface-records/*.json`。此前审阅确认工作簿与 CSV 的 95 条记录一致：30 条通过、43 条部分通过、19 条未通过、1 条未验证、2 条说明。87 项主清单与 6 项板块补充应分别看待，不能把 95 当成原主清单分母。

只将“通过／部分通过”的 73 条记录纳入本次清单，腾讯 K 线拆为日线和最近 5 分钟两个契约，因此有 74 个输入定义。失败与未验证接口不做迁移。部分通过条目保留原始范围和限制，不能仅凭返回非空认为业务语义完整。

产物：

- [输入能力清单 CSV](../coverage/successful-input-capabilities.csv)：便于逐条审阅实际来源、参数来源、刷新节奏、请求间隔、限制和迁移状态。
- [输入能力证据 JSON](../coverage/successful-input-capabilities.json)：关联原记录、原响应、派生结果、源代码和 SHA-256，保存配置/转换代码版本、验证时间及覆盖分母。
- [原接口覆盖清单](../coverage/interface-coverage.csv)：原始状态依据，未改写。
- [离线回归记录](../results/2026-10-03-input-capability-framework-tests.xml)：本次框架测试结果；使用合成夹具，不表示新增接口实测。
- [本阶段核验摘要](../results/2026-10-03-input-capability-framework-verification.json)：配置、清单、实现代码与回归记录的版本哈希及检验统计。

清单生成过程离线校验了成功子集引用的 330 个唯一文件；压缩响应先恢复原字节再校验原哈希。原探针报告里的旧备注单独保留，新的限制说明不覆盖原证据。

全套离线回归为 163 项通过，修改前基线为 137 项通过；没有真实接口请求或生产数据写入。此次新增核验确认的是配置和框架行为，不增加任何上游接口的实测覆盖范围。

## 配置结构

继续使用 `config/providers.yaml`，其中 `providers` 对应现有适配器，`input_capabilities` 保存本次全部输入契约。契约声明不自动创建适配器，也不授予路由资格。

| 配置字段 | 含义 |
|---|---|
| `provider`、`endpoint` | 实际数据来源与端点，避免把上层函数名称当成最终来源 |
| `data_kind`、`data_frequency` | 返回数据形态与数据周期；数据周期与采集刷新频率分别定义 |
| `parameters` | 参数类型、来源、默认值、必填、候选值和数值边界 |
| `request_shape` | 单证券、证券批量、按日快照、全量快照、文件包或分页列表 |
| `request_interval_seconds`、`effective_concurrency` | 请求启动间隔与并发上限 |
| `request_group` | 现有适配器共享的请求组；组内采用最严格间隔和最小并发 |
| `request_limit_enforcement` | 未实现、仅调用边界限速或每次可见物理请求限速 |
| `collection_profile` | `collection.yaml` 中的采集意图，如盘中刷新、盘后、每日 |
| `implementation_status` | 未实现、待迁移、仅验证可用、别名或存在阻碍 |
| `evidence_refs`、`limitations` | 原接口证据编号及本次明确的使用边界 |
| `runtime_endpoint` | 对应现有适配器位置，仅供迁移对照；同一适配器可能提供多个方法 |

参数来源限定为显式上下文：`request`（调用输入）、`config`（固定配置）、`calendar`（调用方提供的交易日）、`metadata`（游标等已存状态）、`dependency`（前置输入结果）和 `credential_ref`（凭据引用名称）。加载器不求值表达式、不读取环境凭据，也不自行请求前置数据。日期、带时区时间、列表、数值和候选值在绑定时校验。来源契约中的参数仍需适配器按原接口格式编码，不能直接将整个配置字典发给上游。

BaoStock 的交易日快照要求提供已知交易日集合；本地证券筛选标为 `local_filter`，不冒充上游范围裁剪。腾讯最近 5 分钟契约禁止历史起止窗口，`count` 限定为 1～320。

`collection.yaml` 中定义了 7 组采集意图：行情盘中 60 秒、新闻盘中 300 秒，以及行情盘后、基础资料每日、事件每日、宏观每日和来源市场每日。所有新意图的 `scheduling_enabled` 为 false。这些数字是初始配置，尚无持续容量实测；没有确定全股票、分组、观察池或轮转覆盖规则。

## 请求行为与正式路由边界

共享请求限速器（Request Pacer）包装现有传输对象，不替换来源 Session、请求头、参数、代理、重试或备用主机。腾讯单证券分钟请求逐个限速；证券批量按批次计算；全量快照按整次计算；未知分页上限的容量预算为无穷大。预算只表示请求间隔成本，网络耗时与重试成本尚未得到实测，不能据此承诺生产完成时限。

EastMoney 原生 Requests 传输保留内部重试，但其内部每次重试尚未被共享限速器逐次控制，所以明确标为 `call_boundary_only`。AkShare、BaoStock 等 SDK 内部请求也未假定已被限速。这些来源的正式路由资格不能仅凭外层间隔字段获得。

原工厂曾在启动时生成新的验证时间，本阶段移除该行为。默认 `load_provider_registry(...)` 在没有元数据证据时返回空集合。传入已打开的现有 `MetadataStore` 才读取能力证据；需在注册表使用期间保持该存储打开。选择时同时复查最新证据与冷却状态，启动后失败/撤销也能阻止选择。

证据须与端点版本、数据集、市场、资产类型、周期、复权方式一致，并满足有效期、非空结果、字段/单位已确认及选择资格。正式角色还要求请求限速实现状态为 `physical_request`。现有证据只提供样例证券集合，因此资格收窄到实际样例，不推导全市场覆盖；原证据的日期窗口仍保留在元数据和清单中，本阶段没有新增历史窗口路由机制。

`include_unverified=True` 仅用于显式构建探针适配器；其能力有效期为过期状态，不能通过正式路由选择。适配器本身仍可被直接调用，因此调用方必须使用路由结果判断资格。输入清单的全部 `eligible_for_production_routing` 均为 false，没有把验证归档自动写入生产元数据。

## 需要保留的业务限制

- ASTOCK-049 实际为东方财富涨停池，归并到 ASTOCK-045；不能作为同花顺涨停原因来源。ASTOCK-050 为强势股池，不能解释为交易所重点监控名单。
- ASTOCK-070 交易日历实际来自新浪；ASTOCK-061 社融实际请求商务部数据站；ASTOCK-062 PMI 来自东方财富。来源名称按已存请求修正。
- ASTOCK-015、024、059、060、086 的零值、筛选、字段、概念归属或分页完整性有阻碍；ASTOCK-029、052 为派生数据。它们在清单中标为 `blocked`，不会作为已就绪的外部输入。ASTOCK-088 保留为 024 的别名。
- BaoStock 行业样例覆盖 5221/5223，只确认沪深样例日期，缺失两只；SDK 解码字段已留存，底层 TCP 原帧不可见。

74 个定义当前分布：53 个未实现、6 个待迁移、6 个仅验证可用、7 个存在阻碍、2 个别名。该状态描述迁移进度，不覆盖原接口验证状态。

## 复现与后续实施

在仓库根目录执行：

```powershell
python provider_validation/tests/prepare_capability_results.py --input-catalog
python -m pytest --junitxml=provider_validation/results/2026-10-03-input-capability-framework-tests.xml
```

第一条只读取已留存证据并重建本阶段派生清单，不刷新原覆盖工作簿。第二条执行现有离线回归及新增边界测试。

下一阶段先按清单选择要迁移的输入，逐条保留已验证脚本的请求和解析行为，建立原脚本与正式适配器的对照；完成离线契约、小范围真实探针、语义验证和数据生产验证后，再授予对应范围的资格。全股票或分组覆盖、调度优先级、断点/补采策略、生产落库和未确认单位均未在本阶段实施。
