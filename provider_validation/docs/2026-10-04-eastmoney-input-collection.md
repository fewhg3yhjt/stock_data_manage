# 东财三项已有接口转换记录

本批修改已有股东户数、分红、资金流 Provider，将成功探针的 SDK 调用接入通用候选采集入口。没有新建 Provider 或字段模板，没有启动自动调度或开放正式路由。

| 输入 | 复用模块和模板 | 来源行数 → 候选行数 | 初始采集策略 |
|---|---|---|---|
| ASTOCK-026 股东户数变化 | `shareholder.py` / `shareholder_count.yaml` | 63 → 63 | `event_daily`，按自然日检查更新 |
| ASTOCK-027 分红送转历史 | `dividend.py` / `dividend_event.yaml` | 28 → 27 | `event_daily`，按自然日检查更新 |
| ASTOCK-028 个股资金流 | `fund_flow.py` / `stock_fund_flow.yaml` | 120 → 120 | `market_after_close`，交易日盘后 |

三项均从 `request.symbol` 绑定证券代码；已有 `providers.yaml` 指定数据集、原 Provider 的 `fetch_history` 方法、策略、3 秒请求间隔及串行限制。股东/分红的初始分页查询和第一页查询各两次，资金流一次；SDK 内部重试的实际物理请求数不可见。来源返回完整可用窗口，不支持配置起止日或固定条数，传入这些参数会拒绝执行。原分类策略未新增具体触发时刻，配置仍为 `scheduling_enabled: false`；本批只完成候选入口，自动调度范围与运行时间后续确认。

## 字段与分红选择

`datasets` 保持原字段类型、单位、必填字段和主键；`normalization` 的原规则保留，追加按输入编号选择的 SDK 中文列映射。字段选择和映射由 YAML 实际驱动，可通过原 CLI 的 `--fields` 筛选。

用户确认：“只接入 27 条已实施事件，预披露方案仅留原始证据”。因此来源 28 行完整保存，标准事件只接入 `方案进度=实施分配` 的 27 行；另存 1 行预披露的来源索引、原行和排除原因。标准主键仍为证券代码与除权日，没有把报告期代替除权日，也没有新增历史方案模板。公告日映射为来源“最新公告日期”；报告期窗口 2001-12-31 至 2026-06-30 指来源历史列表的报告期，不代表除权日期。

股东户数的统计截止日、户数、变动比例与公告日按原列接入。SDK 没有输出前一统计日，因此标准 `previous_end_date` 留空，原响应的 `PRE_END_DATE` 仍可追溯。户均市值、户均持股数量、总市值、资金流净额、分红现金金额及送转比率的单位未独立确认，相应标准字段为空，原数字完整保存在来源行和响应中。资金流的日期、收盘价与涨跌幅按原列映射。资金流五种占比不新增标准列，继续留在来源行。

## 旧实现与成功探针的关系

三个旧调用方式、默认参数和返回合同继续保留。股东旧 `fetch` 默认第一页 10 行；分红旧 `fetch_events` 使用全证券除权日窗口；资金流旧 `fetch_daily` 默认 20 行。这些请求与成功探针不同，因此新候选历史方法直接调用原成功探针的三个 SDK 函数，沿用请求参数、头、Session、环境代理和保守重试，不将旧请求方式冒充验证过的历史输入。

原资金流解析把小单/中单/大单/超大单列顺序理解错了。本批在原 `fetch_daily` 和原归一化规则中修正净额及占比共 10 列：`f53/f54/f55/f56` 分别对应小单/中单/大单/超大单，`f58/f59/f60/f61` 同序对应占比。主力、价格、涨跌幅以及旧请求默认值保持一致。独立归档 CSV 的全部 120 行用于核对修正。

分红仅接入有证据的 `stock_fhps_detail_em` 成功分支；原探针的巨潮备选没有对应成功证据，不继承资格。资金流 SDK 的 `_` 请求时间戳在离线回放时从匹配的原请求恢复，精确匹配归档并在结束后恢复 SDK 时钟；实时调用仍使用原时钟。动态时间戳意味着目前不承诺该端点跨次请求的缓存复用。
