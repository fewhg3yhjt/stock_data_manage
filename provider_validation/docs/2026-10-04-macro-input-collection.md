# PMI 与社融统计月历史输入

## 实现边界

ASTOCK-061 对照商务部数据中心原成功响应，保留 136 个统计月（2015-01 至 2026-04）；ASTOCK-062 对照东财原响应，保留 225 个统计月（2008-01 至 2026-09）。这些是归档返回窗口，不代表当前更新或完整历史认证。

PMI 在原 `providers/eastmoney/financial.py` 增加 `fetch_pmi`，原财务指标、事件、LPR 和可转债方法保持。社融没有已有适配器，仅新增必要的 `providers/mofcom/social_financing.py`。沿用原 SDK，不新增管理层、调度器或归一化体系。

`config/datasets/{social_financing,pmi_history}.yaml` 与同名 `normalization` 文件定义字段和来源映射；输入声明限定原 SDK 的全历史请求，不将股票代码或起止日期变成未实测查询参数，继续引用现有 `macro_daily` 频率配置。候选路由、自动调度和生产写入关闭。

## 语义及传输

统计月份明确映射为 `YYYY-MM`；源 `REPORT_DATE` 只是来源参考日期，不能当作公告发布时间。来源没有发布时间，`publication_time` 为空；`snapshot_at` 使用原响应捕获时间。原 JSON、完整原字段、SDK 解析数值和标准字段分别保存；负值与零值不删除，原空值保持。数值单位待独立认证，标准数值为空。社融原 SDK 的外币贷款字段标签保留在解析证据中，不进一步解释为新的业务指标。

原 AkShare 请求、默认请求头、环境代理、重定向、无显式超时、探测 3 秒间隔和主机暂停保持。PMI 使用原探测适配器 2 次重试、最低退避 5 秒；社融 SDK 自带 `TLSAdapter` 会覆盖 HTTPS 适配器，其 HTTPS 重试上限实际为 0，此行为及加密连接设置保持，不能套用 PMI 的重试参数。SDK 函数和社融 TLS 类源码留证并参与版本哈希。没有显式超时仍可能长时间等待来源。

社融为无请求体 POST。现有捕获器只对此已验证合同启用空请求体校验；严格回放同时核对原记录的空请求体 SHA-256，拒绝非空请求体或缺少对应哈希的归档，防止同 URL 的另一类 POST 被误用。没有扩展为通用 POST 参数系统。底层物理重试仍不逐次观测。

原 PMI 脚本的另一个年度备用函数无成功响应证据，因此只接入已成功的 `macro_china_pmi`。PMI 来源字段按原 SDK 位置解析，同时增加原字段顺序、页数/总数、统计月与参考日一致性检查，避免源顺序改变后静默错列。社融同样检查原字段顺序和统计月唯一性。

## 证据与验证

`results/macro-original-20261004/manifest.json` 保存修改前快照、原成功脚本、限频探测脚本与原始清单关联哈希。`macro-final-20261004/comparison.json` 保存原函数与 Provider 对照：请求、响应、字段、行数、原 CSV、全部原数值和返回月份一致。异常验证包括业务错误、空表、字段缺失/重排、数字错误、月份错误、重复月份、HTTP 错误、页总数与统计月冲突、空 POST 合同、严格回放及 YAML 字段映射/投影。原财务方法也与修改前源码直接对照。

原验证入口扩展 `--verify-macro`，模拟会话/cache 与空值/负值/零值均明确标记为合成证据。`macro-cli-20261004` 保存两个实际命令入口；同前缀 XML/verification.json 保存完整回归和提交前精确字节审计。没有新增真实在线请求，不将候选实现标为生产可用。
