# 财联社电报与新浪全球资讯输入迁移

## 已实现范围

ASTOCK-032 和 ASTOCK-033 各接入原成功归档的最近 20 条。原架构没有这两个新闻适配器，因此仅增加必要的 `providers/cls/news.py`、`providers/sina/news.py`，继续使用原 AkShare 函数；已有股票、期货适配器保持原职责。候选工厂绑定与输入入口扩展，正式路由、自动调度和生产数据写入均关闭。

四份 YAML 为 `config/datasets/{cls_telegraph,sina_global_news}.yaml` 及同名 `normalization` 文件。参数声明限定为 SDK 固定的最近 20 条；历史窗口、证券代码及游标不可冒充已验证查询。采集频率继续引用 `news_intraday`，不另建配置系统。来源字段、解析行与标准字段分别留证；标题、正文、HTML 和原北京时间保持，不推测新浪标题，不清洗文本。快照时间使用原响应捕获时间。

## 请求及重试行为

保留 SDK 原参数、财联社签名算法与 Chrome/114 请求头、新浪默认请求头、环境代理及重定向。原 SDK 没有显式超时，候选保留此行为，可能长时间等待网络；此次不擅自修改原传输层。

原成功低频探测脚本配置的适配器重试上限 2、最低退避 5 秒及主机间隔 3 秒保持。财联社的 SDK 外层最多 10 次尝试及 1、2、4…256 秒退避保持。现有 `captured_requests` 增加显式开关，仅这两项启用原探测的主机暂停：403/429 后暂停，连续两次传输或服务端错误后暂停；暂停异常与原脚本相同，不被 SDK 当作可继续重试的网络异常。底层适配器内部物理重试仍不可逐次观测，不能宣称物理请求次数完整留证。

财联社回放使用原归档的 `last_time` 查询截止时间，只替换函数命名空间的时钟；实际在线路径继续当前时钟。签名留证脱敏，原签名生成算法不变。新浪原脚本先尝试新浪、再尝试东财；此能力只接入已成功的新浪分支，东财备用分支无匹配成功证据，不接入。
